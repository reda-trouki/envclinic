# CLI reference

```text
envclinic [global options] [command] [command options]
```

Running `envclinic` with no command is the same as `envclinic audit`.

## Global options

| Option | Description |
|---|---|
| `--cwd <dir>` | Project directory (default: current directory) |
| `--config <path>` | Config file (default: auto-detected) |
| `--json` | Print machine-readable JSON |
| `--format <format>` | `terminal` (default), `json` or `github` |
| `--quiet` | Only print errors and a summary line |
| `--verbose` | Print resolved settings to stderr |
| `--no-color` | Disable colors (colors are also off when `NO_COLOR` is set or output is piped) |
| `--version`, `--help` | |

## Exit codes

| Code | Meaning |
|---|---|
| `0` | Success. No errors (warnings are allowed unless `--strict`) |
| `1` | Problems found, a `--check` failed, or you cancelled an action |
| `2` | Usage or runtime error: bad option, invalid config, refused write, missing prerequisite |

With `--json`, a code-2 failure prints `{ "success": false, "error": "..." }` so scripts can always parse stdout.

## Commands

### `audit`

The complete audit: env files, unused and undeclared variables, secrets, schema validation, and types freshness.

| Option | Description |
|---|---|
| `--strict` | Treat warnings as errors |
| `--ci` | Non-interactive: no colors; adds GitHub annotations when `GITHUB_ACTIONS=true` |
| `-f, --file <path>` | Env file to audit. Repeatable. Default: `.env` |
| `--example <path>` | Template to compare against. Default: `.env.example`, then `.env.sample` |
| `--ignore <names>` | Variables to ignore. Comma-separated, repeatable, `*` wildcards allowed |
| `--no-scan` | Do not scan source code (skips unused/undeclared variables and hardcoded credentials) |
| `--process-env` | Also validate the real process environment (it wins over env files) |
| `--fix` | Add undocumented variables to the example file. Asks for confirmation |
| `--dry-run` | With `--fix`: show the change without writing |
| `--yes` | With `--fix`: apply without asking (required when there is no terminal) |

`--fix` is deliberately narrow. It appends variable **names with empty values** to your example file, keeps everything already in it, and never touches real env files. It fixes `undocumented-variable` and `undeclared-variable` issues only.

### `check`

Missing, empty, duplicate and invalid variables plus schema validation. No source scanning. Options: `--strict --ci --file --example --ignore --process-env`.

### `secrets`

Potentially exposed credentials and weak secrets, in env files and source code. Options: `--strict --ci --ignore`, and `--env-only` to skip source code.

### `unused`

Potentially unused variables (declared but never read) and undeclared variables (read but never declared). Options: `--strict --ci --ignore`, and `--dir <path>` (repeatable) to choose the directories to scan.

### `validate`

Validates env values against the `schema` in your config. Exits with code 2 if there is no schema, or no env file and no `--process-env`. Options: `--strict --ci --file --process-env`.

### `generate`

Creates or updates `.env.example`. It lists variable **names only**, never values, grouped under headings such as "Database configuration" and "Authentication". Names come from your env files, the schema, and variables read in your source code.

| Option | Description |
|---|---|
| `-o, --output <path>` | File to write. Default `.env.example` (or `generate.output` in config) |
| `--dry-run` | Print the result, write nothing |
| `--force` | Replace the file if it exists |
| `--merge` | Add only the missing variables to the file if it exists |
| `--exclude <names>` | Variables to leave out. Comma-separated, repeatable, `*` wildcards allowed |
| `--no-scan` | Do not detect variables from source code |

If the file exists and you pass neither `--force` nor `--merge`: in a terminal envclinic asks what to do; otherwise it refuses with exit code 2. It never writes to `.env`, `.env.local` or other real env files; only template names such as `.env.example` are allowed.

### `types`

Writes TypeScript declarations (names and types only) for your variables. See [configuration](./configuration.md#types).

| Option | Description |
|---|---|
| `-o, --output <path>` | File to write. Default `env.d.ts` (or `types.output` in config) |
| `--dry-run` | Print the result, write nothing |
| `--check` | Exit 1 if the file is missing or out of date; write nothing. Good for CI |
| `--force` | Overwrite a file that was not generated by envclinic |
| `--no-scan` | Do not detect variables from source code |

Files it generated start with `// Generated by envclinic` and are regenerated freely. A file without that marker is treated as hand-written and is never overwritten without `--force`.

### `framework`

Shows the detected framework, how it reads variables, which prefixes reach the browser, and why it was detected. `--json` prints the same as JSON.

### `init`

Interactive setup that writes `envclinic.config.json`.

| Option | Description |
|---|---|
| `--yes` | Accept detected defaults, no questions (required when there is no terminal) |
| `--force` | Replace an existing config file |
| `--config-format <format>` | `json` (default) or `mjs` |

## Issue codes

| Code | Default severity | Rule | Meaning |
|---|---|---|---|
| `missing-variable` | error | `missing` | In the example file, absent from an env file |
| `undocumented-variable` | warning | `undocumented` | In an env file, absent from the example |
| `empty-variable` | warning | `empty` | Declared with an empty value |
| `duplicate-variable` | error | `duplicates` | Declared more than once in one file |
| `invalid-variable-name` | warning | `names` | Not letters, digits and underscores, or starts with a digit |
| `malformed-line`, `unterminated-quote` | warning | `syntax` | A line cannot be parsed |
| `unused-variable` | warning | `unused` | Declared but not found in scanned source (potentially unused) |
| `undeclared-variable` | warning | `undeclared` | Read in code but not in any env file or the example |
| `dynamic-env-access` | info | | Dynamic access exists, so unused results may be incomplete |
| `exposed-credential` | see [security](./security.md) | `secrets` | A credential-shaped value in an env file or source code |
| `secret-in-example` | warning | `secrets` | The template holds a real-looking value for a secret variable |
| `env-file-not-ignored` | error | `secrets` | An env file with values is not listed in `.gitignore` |
| `public-secret` | warning or error | `secrets` | A secret-looking variable carries a client-exposing prefix |
| `weak-secret` | warning | `weak` | A secret that is short, a placeholder, or low entropy |
| `schema-*` | error | `validation` | A schema rule failed (`missing-required`, `invalid-type`, `invalid-enum`, `invalid-protocol`, `too-short`, `too-long`, `out-of-range`, `pattern-mismatch`, `custom-failed`) |
| `validation-skipped` | info | | A schema exists but there was nothing to validate |
| `types-missing`, `types-outdated`, `types-unreadable` | warning | `types` | `types.enabled` is on and the declaration file is not current |
| `source-file-missing` | info (error if you named the file) | | An env file was not found |
| `example-file-missing` | warning (error if you named the file) | | No example file |
| `no-env-files` | error | | Nothing to audit |
| `unsafe-path`, `file-too-large`, `file-unreadable` | error | | A file was refused or could not be read |
| `non-utf8-file` | warning | `syntax` | The file is UTF-16 (typical of PowerShell `>`). It is read correctly, but most dotenv loaders need UTF-8 |
